# wl-upload 技术文档

## 项目概述

**wl-upload** 是一个高性能的大文件分片上传解决方案，支持客户端并发 Hash 计算和多线程优化，提供分片秒传和文件秒传功能，能够显著提升大文件上传的效率和用户体验。

### 主要特点

- **高性能**：支持多线程 Worker 并发计算 Hash，充分利用多核 CPU 资源
- **智能秒传**：支持分片级和文件级秒传，避免重复上传
- **并发上传**：可配置的并发上传队列，平衡上传速度和系统负载
- **断点续传**：通过秒传机制实现断点续传功能
- **灵活配置**：支持单线程/多线程模式切换，适应不同场景需求

## 核心特性

### 1. 大文件分片上传

- 将大文件按照配置的 `chunkSize` 切割成多个分片
- 支持自定义分片大小，平衡上传效率和内存占用
- 自动处理最后一个分片（可能小于 `chunkSize`）

### 2. 并发 Hash 计算（支持多线程 Worker）

- **单线程模式**：使用单个 Worker 线程串行计算所有分片 Hash
- **多线程模式**：使用 Worker 线程池并行计算分片 Hash，显著提升计算速度
- **系统自适应**：根据 `navigator.hardwareConcurrency` 自动确定线程数
- **可配置**：通过 `enableMultiThreading` 配置项控制是否启用多线程（默认启用）

### 3. 分片秒传和文件秒传

- **分片秒传**：上传前检查分片是否已存在，跳过已存在的分片
- **文件秒传**：文件 Hash 计算完成后立即检查文件是否已存在，如果存在则跳过所有上传步骤
- **去重机制**：服务端自动去重，相同 Hash 的分片只存储一次

### 4. 并发上传队列

- 可配置的并发数限制（`concurrency`），控制同时上传的分片数量
- 自动任务调度，当有可用并发槽位时自动启动待处理任务
- 失败即中止策略，任何分片上传失败立即中止整个上传流程

### 5. 断点续传支持

- 通过秒传机制实现断点续传：重新上传时自动跳过已存在的分片
- 无需额外的断点记录，基于 Hash 值自动识别已上传的分片

### 6. 架构设计理念

#### 6.1 面向对象编程（OOP）

- **类的职责单一**：每个类专注于特定功能
- **封装性**：内部实现细节隐藏，对外提供清晰的 API 接口
- **可扩展性**：通过继承和组合支持功能扩展
- **状态管理**：每个类管理自身状态，通过事件通知外部变化

#### 6.2 分层架构

**分层优势**：

- 职责清晰，便于维护和测试
- 各层可独立演进，互不影响
- 支持水平扩展（无状态设计）

#### 6.3 事件驱动架构

- **解耦设计**：组件之间通过事件通信，降低耦合度
- **异步处理**：Hash 计算和上传任务并发执行，互不阻塞
- **事件流**：`ChunkHashed` → `AllChunksHashed` → `FileHashed` → `QueueDrained`
- **扩展性**：新增功能只需监听相应事件，无需修改现有组件
